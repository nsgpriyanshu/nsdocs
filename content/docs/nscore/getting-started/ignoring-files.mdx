# Ignoring Files

This section explains how to configure ignore files to ensure unnecessary or sensitive files are not committed to version control or processed by formatting tools.

Proper ignore rules keep the repository clean and secure.

---

## Git Ignore

Create a `.gitignore` file in the project root:

```txt filename=".gitignore" showLineNumbers
# Node.js
node_modules/
dist/

# TypeScript
*.tsbuildinfo

# Logs
*.log

# Testing and coverage
coverage/
*.test.js

# IDE-specific files
.vscode/
.idea/
*.sublime-project
*.sublime-workspace

# OS-specific files
.DS_Store
Thumbs.db
ehthumbs.db
desktop.ini

# Environment variables
.env

# Miscellaneous
!.gitignore
````

---

## Prettier Ignore

Create a `.prettierignore` file to exclude files and folders from formatting:

```txt filename=".prettierignore" showLineNumbers
# Ignore artifacts
build
coverage
node_modules
.next
```

This prevents Prettier from processing generated or external files.

---

## ESLint Ignore

It is also recommended to create an `.eslintignore` file:

```txt filename=".eslintignore" showLineNumbers
# Ignore artifacts
build/
coverage/
node_modules/

# Ignore compiled output
dist/
```

This ensures ESLint only checks relevant source files.

---

## Summary

With ignore files properly configured:

* Sensitive files remain untracked
* Generated files stay out of version control
* Linting and formatting tools run more efficiently

You can now continue development with a cleaner and safer repository.
